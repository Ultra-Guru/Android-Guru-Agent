# 全栈工程师知识库

## 必看内容

- **端到端所有权心智**：全栈不是"什么都会一点"，而是**对一条功能链
  负全责**（前端 → API → 数据 → 部署可观测）。每个决策问三遍：
  这个改动对链上下游的影响？契约变了吗？回滚怎么做？
- **契约先行**：前后端之间的唯一事实是 API 契约（schema）。
  先定契约（字段/错误码/分页/幂等），再各自实现 —— 契约变更必须
  显式版本化，禁止"顺手加字段"。
- **最小变更交付**：能上线的最小切片优先（竖切），
  而不是把某一层做完美。跨层重构一次只动一层。
- **数据比代码贵**：迁移必须向后兼容（只加不删，两段式）；
  任何删字段/改语义的迁移要有回滚窗。数据损坏没有 undo。
- **三道验证门**：本地（类型/单测）→ CI（构建/门禁）→ 线上
  （冒烟+观测）。跳过任何一道都是在赌。
- **不可观测 = 不存在**：新功能上线必须带观测（日志/指标），
  否则故障时两眼一抹黑。

## 1. 竖切交付

```text
用户故事："用户可以收藏商品"
竖切 =  DB 字段 + POST/DELETE 端点 + 前端按钮态 + 列表页角标
横切（错误示范）= 先把"整个收藏系统"后端做完，前端下周再接
```

- 切片判据：用户可见价值的最小单位；每片独立可验证可发布。
- 每片完成定义：本地测过 + CI 绿 + 冒烟通过 + 观测就位。

## 2. API 设计

- REST 资源命名：名词复数（/orders）；动作子资源
  （/orders/{id}/cancel）；层级 ≤2 层。
- 方法语义：GET 幂等无副作用；PUT 全量替换幂等；PATCH 部分；
  POST 创建/非幂等动作；DELETE 幂等。
- 版本化：/v1 前缀（简单）或 header（严格）；破坏性变更升主版本。
- 响应包络：{ code, message, data } 或直接资源 + 错误时统一错误体
  （全栈内自洽即可，别混两种风格）。

## 3. 错误体系

| 层 | 码段 | 例 |
| --- | --- | --- |
| 参数 | 4xxxx | 40001 缺字段 |
| 认证 | 401xx | 40101 token 过期 |
| 权限 | 403xx | 40301 非资源 owner |
| 资源 | 404xx | 40401 不存在 |
| 冲突 | 409xx | 40901 重复提交 |
| 上游 | 502xx | 50201 依赖服务超时 |
| 系统 | 500xx | 50001 未知 |

- 错误体三要素：code（机器分支）/ message（人读，可本地化）/
  hint（前端引导动作）。
- 禁止裸 500 —— 未知错误也要带 trace_id 关联日志。

## 4. 集合接口

| 需求 | 约定 |
| --- | --- |
| 分页 | ?page=1&page_size=20（或 cursor 式 ?after=id） |
| 排序 | ?sort=-created_at（- 降序） |
| 过滤 | ?status=active&created_at.gte=…（保留字转义） |
| 总数 | 响应带 total（cursor 式带 has_more） |

- 大数据集用 cursor（页码深翻页代价高且不稳定）。
- 过滤字段白名单校验（防注入与滥用）。

## 5. 幂等

- 写操作带 Idempotency-Key 头（客户端 UUID）；
  服务端同键 24h 内返回首结果。
- 天然幂等：PUT/DELETE（按资源 id）。
- 支付/下单类：状态机 + 唯一约束兜底（双保险）。

## 6. 认证深水

教科书给三选一表（session/JWT/OAuth）；生产线的真问题在这：

- **会话固定的修法是轮换**：登录成功瞬间必须重发新 session id
  （旋转旧值）—— 登录前的匿名会话 id 是劫持载体。JWT 同理：
  登录响应换新 token，不沿用匿名期 token。
- **refresh token 轮换 + 复用检测**（2025 事实标准）：refresh
  一次性使用、每次换新；旧 token 再现 = 泄露信号 →
  **撤销整个 token family**（一家人全下线）。无轮换的长效
  refresh 是最大资产泄漏面。弱网宽容：10s 宽限窗防竞态，
  但宽限窗内仍计数报警。
- **CSRF 与 SameSite 互动矩阵**：SameSite=Lax 挡跨站 POST，
  但**不挡顶级导航 GET**（链接跳转仍带 cookie）；老浏览器
  回退 + 子域信任问题意味着 CSRF token 同步模式仍是标配
  而非历史包袱。无状态侧最小方案：双提交 cookie。
- **token 存储面取舍**：内存 access（15min）+ httpOnly
  refresh cookie（路径限定 /refresh + SameSite=Strict）——
  localStorage 存 refresh = 把"偷了就能续命"的钥匙放 XSS 口袋。
- **密钥管理**：签名密钥走 KMS/密钥服务，代码库零落盘；
  轮换用 kid 多密钥并存（JWKS 端点按 kid 选钥）：新钥签、
  旧钥验，过渡一个周期后退役。非对称优先（RS256/EdDSA）：
  下游用公钥验签，不共享私钥。
- **注销的真义是撤销链**：logout 同时清 access（前端丢弃）、
  refresh（服务端黑名单/删除）、会话记录（标 revoked）；
  只清前端 = 没注销。改密码全端失效：tokenVersion/
  密码哈希参与会话派生。
- **passkeys（WebAuthn）2025 口径**：注册/认证两个 ceremony，
  服务器只存公钥 + credentialId + signCount；challenge ≥16
  字节随机；origin/RP ID 绑定天然防钓鱼。作为第二因子或
  渐进替代接入（resident key: preferred），双轨期很长 ——
  没有恢复流程的 passkey 上线等于给客服挖坑。
- **时钟与算法底线**：exp 校验留 30-60s 偏移窗；算法白名单
  显式列（拒绝 alg:none；按 kid+算法固定绑定，防 HS/RS
  混淆攻击）。

## 7. 授权

- 模型选择：RBAC（角色）起步；资源级判定（owner/团队）叠加
  policy 层。
- 前端只做展示级隐藏（真校验必在服务端）—— 前端藏按钮是 UX 不是安全。
- 越权测试用例：换 id 访问他人资源必须 403。

## 8. 数据建模

- 第一范式起步，反范式只为读性能且度量证明。
- 主键：自增（简单）vs 业务键（同步场景必须）vs UUID（分布式）。
- 时间字段：created_at/updated_at 全表标配（迁移与审计依赖）。
- 软删除：deleted_at（需要恢复/审计时）；硬删除配归档表。
- 大字段拆表（热行变窄）；枚举用 lookup 表或受控字符串（跨端一致）。

## 9. 迁移

两段式模板（扩-停-缩）：

```text
阶段1（扩）：加新列/新表，双写（老读新写 or 新读老写灰度）
阶段2（停）：确认无回退需求（观察窗 ≥ 一个发布周期）
阶段3（缩）：删老列 —— 单独发版，删前先"代码不再引用"一版
```

- 禁止单发布里"删字段"；任何删动作有回滚窗。
- 数据回填分批（每批 ≤10k 行 + 限速）；回填脚本幂等可重跑。

## 10. 缓存

| 层 | 手段 | 失效 |
| --- | --- | --- |
| HTTP | Cache-Control/ETag | 时间/协商 |
| 应用内 | LRU 内存 | 容量/TTL |
| 分布式 | Redis | 主动删/过期 |
- 纪律：先度量（缓存收益 = 命中率 × 单次代价）；键带版本前缀
  （结构变更整体失效）；防击穿（singleflight/锁）。

## 23. 测试策略

金字塔：单元 70% / 集成 20% / 端到端 10%。

- 单元：业务逻辑（服务层）—— 快而稳。
- 集成：API 契约 + DB 映射（拉起真依赖或容器）。
- 端到端：关键用户流（登录/下单/支付）。
- 纪律：测试速度劣化 >10min 就没人跑了 —— 保持快。

## 24. 契约测试

- 前后端共享 schema（OpenAPI/TS 类型）单源生成两端类型。
- CI 里跑兼容性检查（新增字段向后兼容；删除字段需版本升级）。
- mock 服务器从 schema 生成（前端不等后端）。

## 25. 部署

| 形态 | 适用 |
| --- | --- |
| 容器 + 编排 | 团队有平台能力 |
| 无服务（FaaS） | 突发/低频 |
| 单机 + 进程管理 | 起步期（别看不起，够用就好） |
- 发布产物不可变（镜像/包指纹）；配置外置。

## 26. 环境矩阵

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| local | 开发 | 种子/假数据 |
| staging | 预发验证 | 脱敏近似生产 |
| prod | 生产 | 真实 |
- 环境差异是 bug 温床：配置驱动差异，代码路径统一（feature flag）。

## 27. 配置

- 12-factor：配置来自环境（env/secret manager）；
  代码不含环境判断。
- 分层：默认值 → 环境变量 → 启动参数（右覆盖左）。
- 变更走流程（配置也是发布物，有审计）。

## 28. 特性开关

- 开关粒度 = 回滚粒度；开关短命（功能稳定后拆走）。
- 分类：发布开关（灰度）/实验开关（A/B）/运营开关（降级）。
- 纪律：开关不是架构债的遮羞布 —— 三类之外别加。

## 29. 灰度

- 顺序：内测 → 1% → 10% → 50% → 全量；每档观察窗 ≥ 半小时
  （核心指标无回归再推）。
- 按维度放行：用户 id 哈希 / 白名单 / 地域。

## 30. 回滚

- 回滚是能力不是失败：预演（演练回滚路径）+ 触发条件写死
  （P95 >1s 持续 5min 即回）。
- 代码回滚 ≠ 数据回滚：迁移设计保证新旧代码都能跑（9 节两段式）。

## 31. 值班

第一响应 5 分钟动作：

1. 看大盘（哪个指标异常）。
2. 最近发布（谁动了什么）→ 优先怀疑新发布。
3. 决策：回滚 or 扩容 or 降级（开关）。

## 32. 复盘

模板：时间线 / 影响面（用户数/时长）/ 根因（技术+流程）/
改进（落到 hook/CI/约定的具体条目 + 责任人）。

- 无责文化（对事）；改进项必须有验收条件。

## 33. SLO

| 级 | 指标 |
| --- | --- |
| SLI | 可测指标（成功率/P95） |
| SLO | 目标（99.9% / 300ms） |
| 错误预算 | 1-SLO（预算内不折腾可靠性） |

- SLO 定了就要有看板与告警绑定，否则是墙纸。

## 34. 成本

- 每功能三问：存储成本/计算成本/带宽成本量级。
- 高频接口 = 成本热点；缓存与批处理是前两杠杆。
- 闲时缩容/按量计费（云形态）。

## 35. 前端工程

- 构建：按路由分包（code splitting）；产物指纹缓存。
- 依赖锁定（lock 文件）；node 版本统一（engines 声明）。
- 代码规范自动化（lint + format 进 pre-commit，人只管例外）。

## 36. 组件设计

- 状态less 优先：数据进（props）/事件出（callback）。
- 复用三验：同文案？同行为？同数据形态？都同才抽组件。
- 页面级组件只做组装；通用组件目录禁止引用页面。

## 37. 前端状态

| 状态 | 放哪 |
| --- | --- |
| 服务端数据 | 缓存层（query 库/手写 store + 失效键） |
| URL 状态 | 路由参数（可分享/可回退） |
| 会话态 | 全局 store（用户/主题） |
| 表单瞬态 | 组件本地 |
- 服务端数据是缓存问题不是状态问题（失效键设计好就稳）。

## 38. 路由

- 路由即状态：可分享/可回退/可深链 —— 能进 URL 的都进 URL。
- 嵌套路由按布局切分；懒加载守卫（权限/认证）集中一个中间层。

| 手段 | 时机 |
| --- | --- |
| 路由分包 | 默认 |
| 虚拟列表 | >100 行 |
| 图片懒加载 + 尺寸占位 | 默认 |
| 防抖搜索 | 输入类默认 |
| 转场动画只用 transform/opacity | 默认 |

## 40. 前端测试

- 组件测试（render + 交互断言）为主；端到端只盖关键流。
- 快照测试慎用（噪音大）；无障碍断言顺手写（41 节双赢）。

## 41. 无障碍

- 语义标签优先（label 关联）；键盘可达（tab 顺序）；对比度 ≥4.5:1。
- 动效可关；焦点管理（弹层进出焦点归还）。

## 42. i18n

- 文案全资源化；插值占位符统一（CI 校验镜像，本仓库模式）。
- 日期/数字本地化（Intl）；RTL 布局用逻辑属性（start/end）。

## 43. 后端工程

- 分层：路由（校验/装配）→ 服务（业务）→ 仓储（数据）；
  层间单向依赖。
- 每层可单测：服务不依赖框架类型（可纯 JVM/JVM 测试）。

## 44. 服务层

- 用例方法命名讲业务（placeOrder）不讲技术（doStuff）。
- 一个用例一个事务边界（46 节）；返回领域对象不是 DB 行。

## 45. 数据访问

- 仓储接口 + 实现分离（可换/可 mock）。
- N+1 检测（每请求 SQL 计数）；列表接口显式 select 列。

## 46. 事务

- 最小边界：跨表一致才开事务；只读查询不开。
- 长事务毒药：事务内禁远程调用（锁持有时间暴涨）。

## 47. 并发控制

| 策略 | 适用 |
| --- | --- |
| 乐观（version 字段） | 低冲突编辑 |
| 悲观（select for update） | 强一致短临界区 |
| 队列串行化 | 天然单写者场景 |
- 丢失更新测试用例（双端并发改同资源）。

## 48. 日志

- 结构化（键值对）；一条一事；级别纪律
  （error=需人看 / warn=自动恢复 / info=关键路径节点）。
- trace_id 贯穿（入口生成，下游透传）。
- 禁敏感值（手机号/ token 脱敏）。

## 69. HTTP 语义深水

方法幂等表人人会背；语义深水在边缘：

- **安全方法的缓存副作用边界**：GET 契约上"客户端可重试
  无损"—— 把付费/发邮件塞进 GET 是自毁缓存层与预取器
  （speculation rules 时代 GET 会被浏览器预取，副作用=事故）。
- **PATCH 的两种方言**：JSON merge patch（RFC 7386，null 删键）
  vs JSON Patch（RFC 6902，op 路径操作）—— 契约必须写明
  Content-Type（merge-patch+json / json-patch+json），
  混用是数据删除事故源。
- **303 vs 307/308**：POST 后想让客户端改用 GET → 303；
  保留原方法 → 307（临时）/308（永久）。302 是历史混合
  语义，新代码禁用。
- **421 Misdirected Request**：SNI/Host 路由错位（多租户
  TLS 网关常见）—— 比 404 更诚实的"你敲错门了"。
- **428 Precondition Required**：状态机资源（订单/工单）
  强制客户端带 If-Match 才许写 —— 把乐观并发从"建议"
  升级为协议要求（71 节）。
- **H/2→H/3 的 API 语义面**：多路复用后"域内 6 连接"的
  前端预算消失；H/3（QUIC）把传输层队头阻塞挤掉 —— 但
  服务端单流慢仍拖整体，超时预算按"流"而非"连接"设计。

## 70. 状态码深水

常见码表略；语义灰区与客户端行为契约：

- **429 vs 503 分工**：429=配额策略（知道要等多久，
  Retry-After 给秒数）；503=容量/故障（Retry-After 是估计）。
  客户端对 429 停手、对 503 走熔断路径 —— 混用会让重试
  风暴逻辑失效（82 节联动）。
- **304 不是简单的 200 替代**：命中条件请求时 304 不带体；
  If-None-Match 优先于 If-Modified-Since；304 响应仍可带
  Cache-Control 更新（"校正"缓存策略的机会）。
- **409 vs 422 vs 428**：状态冲突（重复创建/违反状态机）
  409；语义校验失败 422；缺前置条件 428。参数语法错 400
  —— 三层口径写进契约，前端错误分支才有结构可依（3 节）。
- **451 与合规**：法务原因拒绝服务用 451（Link 指向说明页）
  —— 比 403 更可审计。
- **5xx 是负载信号**：网关聚合上游 5xx 比例是熔断器输入；
  服务自己永远别把业务错包成 500（trace_id 关联丢失，
  3 节红线）。
- **幂等重放的响应契约**：同 Idempotency-Key 重放返回
  **首结果**（含原状态码）而非 4xx —— 断线重连靠它对账
  （5 节）。

## 71. 请求头深水

- **乐观并发双头**：If-Match: <ETag>（强校验，不匹配 412/
  428）；If-Unmodified-Since 是弱兜底（秒粒度）。写接口
  要求二者其一 —— 并发编辑事故（176 节）的协议级解。
- **Range 合法形态**：单区间 bytes=0-499；多区间
  bytes=0-9,100-109 服务端可回 206 多部分或整体 200 ——
  客户端两者都得处理；If-Range 配 ETag 决定"变了就别续传"
  （78 节下载流）。
- **幂等键指纹进阶**：同 key 不同 body 是攻击/缺陷 ——
  key 可叠 body hash 校验，不一致直接 422（5 节）。
- **信任边界头**：X-Forwarded-For 只可信自家 LB 的第一跳；
  Forwarded（RFC 7239）是标准替代 —— 直连暴露的端口绝不
  解析 XFF 做鉴权（伪造链是无中生有的洞）。
- **Expect: 100-continue**：大请求体先问后发；中间设备吞
  100 会让客户端等到超时才发体 —— 网关超时要显式放行。
- **Prefer: return=minimal**：让服务端裁剪响应（PATCH 只回
  元数据）—— 移动端省流量的标准姿势。
- **X-Request-Id 双向契约**：客户端生成 + 服务端透传/回显；
  日志、trace、客服工单三处同 id（48 节结构化日志对账）。

## 72. 响应头深水

- **Cache-Control 灰阶**：no-store（彻底不存）≠ no-cache
  （可存但每次验证）≠ max-age=0, must-revalidate；
  immutable 配内容指纹 URL（/app.3f9d.js）：指纹资源
  max-age=31536000, immutable，HTML 永远 no-cache。
- **stale-while-revalidate / stale-if-error**：过期后先回旧值
  再后台刷新；故障时降级旧值 —— API 高可用感的来源。
- **ETag 强弱**：弱 ETag（W/"x"）语义等价即可；CDN 压缩
  转换会改强 ETag —— 内容协商场景 Vary 列全
  （Accept-Encoding），漏配=缓存串页。
- **Vary 是缓存键的一部分**：Vary: Accept-Language 意味着
  每种语言一份缓存槽；个性化响应加 Cache-Control: private
  防共享缓存串数据。
- **Deprecation + Sunset + Link rel="deprecation"**：下线
  API 的标准三头（RFC 8594 Sunset 给日期）—— 监控抓取做
  客户端升级倒计时（179 节版本公告联动）。
- **Retry-After 两种形态**：秒数或 HTTP-date；429 用秒数+
  随机抖动（82 节），503 用日期。
- **Clear-Site-Data: "cache","cookies"**：登出/换号时让浏览器
  主动清 —— 服务端撤销链的客户端补完（6 节）。

## 73. Cookie 深水

- **前缀是安全属性不是装饰**：__Host- 要求 Secure+无
  Domain+Path=/（绑定当前主机，子域注入免疫）；__Secure-
  只要求 Secure。会话 cookie 一律 __Host- 起名。
- **第三方 cookie 已死（2025 现实）**：Safari/Firefox 全拦，
  Chrome 走用户级限制；跨站 iframe 想带 cookie 必须
  SameSite=None; Secure; **Partitioned**（CHIPS：按顶级站
  分区存储）。无 Partitioned 的第三方会话方案按"已死"
  设计 —— 嵌入式 SaaS 改 token/POST message 通道。
- **SameSite 细粒度**：Lax 只放行顶级导航的安全方法；
  Strict 连导航都不带（跨站跳入看起来未登录）。合理组合：
  Strict 会话 + Lax CSRF 敏感位 + 6 节 CSRF token 兜底。
- **大小与数量预算**：单 cookie ≤4KB、每域 ~50 个 ——
  本地化串/偏好树放 localStorage，会话引用瘦身到单 id。
- **寿命语义**：会话 cookie（无 Max-Age）= 浏览器生命周期；
  持久 cookie 显式 Max-Age —— "记住我"分层（30 天 vs
  会话级），滑动续期在 6 节轮换里做，不在 Max-Age 上加码。
- **Domain 的子域放大**：Domain=.example.com 全子域共享 ——
  子域 XSS 即全站会话劫持；SaaS 顶层域默认不带 Domain。

## 74. CORS 深水

- **CORS 保护的是用户不是服务器**：没 CORS 拦截，请求照样
  打到服务端 —— CORS 只是浏览器拒绝把响应交给跨源 JS。
  服务端鉴权必须独立存在（Cookie 会话 + CSRF 才是防线，
  6/73 节）。
- **预检缓存**：Access-Control-Max-Age（Chromium 上限 2h、
  Firefox 24h）—— 每个跨源接口都值得回，省一次 OPTIONS
  往返；预检缓存按 URL 不按方法，改头即失效。
- **凭证模式的雷**：Allow-Credentials: true 时 Origin 必须
  精确白名单回显（带凭证时回 * 直接违规）—— 反射型
  Allow-Origin 是账号代管事故的标准剧本。
- **Vary: Origin**：共享缓存（CDN）按 Origin 分槽 —— 漏写
  = A 站拿到 B 站的 CORS 响应缓存，跨用户串数据。
- **本地/私有网络（2025 推进）**：PNA/LNA 要求公网页面访问
  内网 API 前先预检授权 —— 开发环境 "localhost API 被浏览器
  拦"的新根源；解法是显式 dev 网关而非绕过。
- **WebSocket 不走 CORS**：升级握手不受同源策略约束 ——
  WS 的鉴权必须自己做（75 节）；把"浏览器会拦"当鉴权是
  认知错误。

## 75. WebSocket 深水

- **鉴权窗口选择**：cookie 随握手自动带（注意 SameSite=Lax
  会拦跨站 WS）；或握手 200 后**首帧 auth**（自管 token，
  验过才进业务路由）—— 内网推荐首帧，会话边界自己控制。
- **粘性会话**：升级落在某 LB 节点，后续帧必须回同一节点 ——
  网关级 WS 代理或按会话哈希粘性；K8s 下 headless service
  + 长连接是坑源（193 节）。
- **背压**：服务端队列深度满时停读或断开 —— 无背压的广播
  服务在慢客户端上内存爆炸；客户端同样查 bufferedAmount
  再发。
- **permessage-deflate 压缩炸弹**：小帧可解出 GB 级 ——
  网关限压缩窗口（maxWindowBits）或干脆关。
- **关闭码分流**：1000 正常/1001 端点走/1006 异常（不回
  close 帧的断连）/1011 服务端错 —— 客户端重连策略按码
  分流：1006+退避重连，1000 不重连。
- **断线恢复协议自建**：WS 无消息回放 —— 序号+游标
  （last_seq）在重连首帧上报，服务端补发缺口；SSE 的
  Last-Event-ID 是现成对照（76 节）。

## 76. SSE 深水

```text
Content-Type: text/event-stream
id: 42
data: {"tick":1}
retry: 3000
（重连后带 Last-Event-ID: 42 请求头回来）
```

- **自动重连是协议内建的**：断线后浏览器按 retry（毫秒）重连
  并带 **Last-Event-ID** —— 服务端必须实现按 id 补发，否则
  重连=丢消息。id 必须单调（全局序号或时间戳+序号），倒退
  的 id 会卡死补发。
- **心跳防中间设备**：代理/LB 对静默连接掐空闲（常见
  30-60s）—— 每 15-25s 发一行注释（: ping）保活。
- **HTTP/1 遗产**：每连接占一个 TCP/6-slot —— 同域多标签页
  会饿死其他请求；H/2 多路复用解除，但代理缓冲必须关
  （X-Accel-Buffering: no），否则事件攒批到达。
- **事件路由**：event: 类型字段让单连接多路订阅；data 多行
  = 多 data: 行拼接。二进制别用 SSE（那是 WS 的事）。
- **扇出架构**：应用层发 Redis pub/sub（或 Stream），网关
  层订阅转 SSE —— 应用重启不断连接（网关保活），配合
  Last-Event-ID 从 Stream 补发（107 节事件驱动）。
- **鉴权**：EventSource 不能自定义头 —— token 走 query
  （用短时 token 降低日志泄漏面）或 cookie（73 节语境）。

## 77. 推拉选型

推送不是越实时越好 —— 按更新频率×一致性需求选型：

| 需求 | 选型 | 理由 |
| --- | --- | --- |
| 分钟级容忍（仪表盘） | 定时轮询 + ETag 协商 | 304 免回体，成本最低 |
| 10-30s 级、弱网友好 | 长轮询（hold 25s） | 兼容老代理；但每请求占一个服务并发 |
| 服务端单向流 | SSE（76 节） | 自带重连+补发；HTTP 基建全兼容 |
| 双向协作/游戏 | WS（75 节） | 真双向；鉴权/背压/恢复全自建 |
| 跨进程/服务广播 | 消息队列扇出（19 节） | SSE/WS 只是"最后一跳" |

- 轮询的进阶是**协商轮询**：请求带 If-None-Match，304 即
  "无变化" —— 高频轮询带宽从 KB 级降到头几十字节。
- 客户端节律：可见性感知（document.visibilityState 暂停）、
  退避对 429/503、随机抖动防整点齐射（82 节口径）。

## 81. 限流

算法表略；分布式生产线的三难与解：

- **分布式计数的原子性**：Redis 计数用 Lua/原子命令一步完成
  "判+扣"，禁 GET→INCR 两步（竞态窗口内全员放行）；键过期
  配随机抖动防边界齐刺。
- **GCRA/漏桶优于固定窗口**：理论平滑无边界突刺，内存 O(1)
  （每用户一个时间戳）—— 高并发网关的主流实现。
- **分层限流**：LB/网关（IP 粗粒度防 DDoS）→ 应用（用户/
  接口配额）→ 数据层（连接池/行锁）；每层目的不同，别指望
  一层包打。
- **响应契约**：429 + Retry-After（秒）+ X-RateLimit-* 三件套；
  让客户端可编程退避（82 节），而不是猜。
- **准入控制优先于排队**：DB 连接池打满时直接 503+熔断 ——
  排队只会让 P99 全面劣化（Little's law：到达率>服务率，
  队列必然发散）。
- **旁路与降级**：健康检查/探活豁免；限流器自身故障时的
  策略（Redis 挂了放行还是拒绝）要显式定 —— 默认拒绝是
  可用性事故，默认放行是保护失效；二选一并写进值班手册
  （117 节）。

## 82. 重试

- **重试预算**：全局允许的重试比例（如 ≤20%）而非每请求
  次数 —— 客户端各重试 3 次，聚合到上游就是 4 倍流量；
  重试风暴杀服务的速度比故障本身快。
- **退避+抖动必须组合**：指数（0.5s→1s→2s）+ 全额抖动
  （random(0, delay)）；无抖动的同步退避=定时齐射。
- **只重试幂等面**：GET/PUT/DELETE + 带 Idempotency-Key
  的 POST（5 节）；写无幂等键就不自动重试 —— 交给用户
  手动。
- **对冲请求**：P99 尾延迟场景发对冲副本（首个成功者胜），
  限 1 次且全局对冲率受限 —— 只对读路径且下游有冗余时用。
- **熔断与重试联动**：熔断打开后连重试资格一起停；半开只
  放 1 个探测请求 —— 两个机制共享失败计数才不会打架。
- **服务端配合**：明确 Retry-After、超载时尽早 503（fail
  fast 比挂 30s 便宜）、幂等键存储 TTL ≥ 客户端最大重试窗
  （70 节契约）。

## 123. 文档

- README（跑起来）+ docs/（架构/约定）+ ADR（决策记录）。

## 124. review

- diff 可读（无格式化噪音）；
- 契约变更显式标出；
- 迁移单独 review（风险最高）；
- 新依赖必要性；
- 观测/开关/回滚三件随行。

## 125. 协作

- 任务粒度：一人一天内；
- 每日同步讲阻塞不讲进度；
- 阻塞超 2h 升级（别闷头）。

## 143. 问答·进阶

| 缓存一致性最强方案？ | 写穿透+失效广播；代价高，多数场景 TTL 足够 |


## 11. 状态同步

前后端对"同一份数据"的认知同步三口径：

| 口径 | 手段 | 失效条件 |
| --- | --- | --- |
| 拉 | query 缓存 + 失效键 | 键设计（资源 id+版本） |
| 推 | SSE/WS 广播变更事件 | 75/76 节选型 |
| 混合 | 拉为主 + 关键写后失效广播 | 大多数场景 |
- 服务端数据是缓存问题：失效键错了，其他都白搭（37 节）。

## 13. 上传

链路：选文件（accept/大小预检）→ 直传（预签名）或走网关 →
服务端登记（hash 去重秒传）→ 异步后处理（96 节剧本）。
- 大文件：分片 + 断点续传（>50MB 启用）。
- 安全：类型白名单（魔数校验 > 扩展名）+ 病毒扫描入异步链。
