## 必看内容

- **工具面就是能力面**：动手前先 `list` 类探查（文件/终端/浏览器/设备/
  记忆五大族）。禁止假设能力存在或不存在 —— 探查动作永远先于方案陈述。
- **工作区路径口径**：`/workspace/...` 是 guest 侧路径；宿主侧由工具层统一
  解析。写文件优先 CodeWrite/FileWrite，读优先 CodeRead（带诊断与行号
  契约）；`../` 越界被 FilePathSafety 拒绝（SANDBOX_VIOLATION）是纪律不是 bug。
- **长任务纪律**：超过一屏的产出先列计划（Plan）再动手；每步最小可验证
  单元推进；出错回退而不是堆补丁；连续两次同工具同参数失败即换策略。
- **HTML 产物双查**：写出 .html 后先 HtmlAnalyzeLayout 静态验证（骨架/
  响应式/可访问性），需要浏览器内核的真实渲染几何再用 BrowserAnalyzeLayout
  动态复核 —— 两工具互补，缺一不可。
- **停止条件**：用户喊停；权限被拒（解释原因，不绕路）；自身循环检测
  触发（换方法或问用户）。
- **回复口径**：结论先行（用户要答案不是过程诗）；关键数字给出处；
  不确定就说不确定（附验证计划），禁止把猜测包装成事实。

## 1. 工具选择决策树

按「要动的东西」选族：

```text
要读/写文件？
├─ 编码场景（代码/结构化文本）→ code_* 族（CodeRead/CodeWrite/CodeEdit，带诊断回注）
└─ 通用文件（任意路径/二进制附近）→ file_* 族（FileRead/FileWrite/FileGlob/FileEdit）
要跑命令？
├─ 结构化（要输出/超时/等待）→ TerminalRun + TerminalWait + TerminalObserve
├─ 一次性快验证 → ShellExecute 兜底
└─ 长驻会话（交互式 CLI）→ TerminalCreate + TerminalWrite
要看/操作网页？
→ BrowserNavigate（开页）→ BrowserSnapshot（交互元素）→ BrowserAnalyzeLayout（布局几何）
   → BrowserClick/BrowserInput（操作）→ BrowserExtractContent（抽内容）
要控制设备？
→ 设备族（App 管理/系统控制/UI 自动化/传感器），按权限门提示走
要记/回忆？
→ MemoryRecall 宏工具（主动查）；写入由 CS-Mem 自动采集（无需显式）
要问用户？
→ AskUser / AskUserChoice —— 别在回复文本里"等"用户
```

- 选型纪律：语义化工具优先于逃生舱（executeJs 只有语义工具覆盖不到时用）。

## 2. 工作区与路径

- 默认工作区：`<filesDir>/linux/workspaces/default`（= Ubuntu 会话的
  guest `/workspace`）；Code 屏切换工作区后 code_* 族根随之切换。
- 相对路径按当前工作区根解析；绝对路径须在根内（越界拒绝）。
- 产物落位约定：报告/页面 → `reports/`；脚本 → `scripts/`；
  临时 → `tmp/`（任务收尾清理）。
- 找文件三件套：FileGlob（模式）→ FileSearch（内容）→ CodeRead（读）。

## 3. 终端族工具

| 意图 | 工具 | 要点 |
| --- | --- | --- |
| 跑一条命令拿结果 | TerminalRun | 结构化输出/超时/退出码 |
| 等长命令完成 | TerminalWait | 条件等待（提示符/静默/文本） |
| 观察会话 | TerminalObserve | 拿屏幕快照不注入 |
| 交互式 CLI（vim/top/adb shell） | TerminalCreate + TerminalWrite | 会话句柄复用 |
| 杀/收 | TerminalSignal / TerminalClose | 优雅先，强杀后 |
| 诊断链路 | TerminalDiagnostics | 先诊断后行动 |

- 命令纪律：先 DryRun 心算副作用；输出体积预估（>50KB 加管道过滤）。

## 4. 浏览器族工具

标准流：BrowserNavigate（wait_for 关键元素）→ BrowserSnapshot（拿
ref 体系）→ 操作（Click/Input/Select/Scroll/PressKey）→ 
BrowserExtractContent（article/tables/links/meta 四模式）→
BrowserAnalyzeLayout（布局/溢出诊断）。

- ref 失效（SPA 局部刷新）：BrowserLocate 按文本重锚定。
- 多页并行：BrowserTabs（list/new/switch/close）管理上下文，
  切换后必须重新 Snapshot。
- 下载产物：BrowserDownloadList 查进度。
- 人工接管守卫：工具返回 SYSTEM_LOCKED 时等待，不要重试。

## 5. 设备族工具

- 应用管理（安装/卸载/启动）；系统控制（亮度/音量/壁纸）；
  UI 自动化（点击/输入/滑动 —— 权限链见 10 节）；传感器读取。
- 纪律：动作类先说意图再执行（用户可见）；传感器类任务注明采样窗口。
- 安全线：付费/敏感动作（短信/电话）默认逐次确认 —— 这是设计不是故障。

## 6. 记忆族

- 主动查询：MemoryRecall（按关键词召回相关片段）；
  命中率高的是"事实类"（做过什么/偏好/约定），低的是"数值类"（用文件）。
- 写入是自动的（执行时隐式采集）—— 不需要"记住这个"指令；
  用户明说要固化时写入文件而不是依赖记忆。

## 7. 计划模板

复杂任务先产出计划（用户可否决）：

```text
目标：<一句话>
步骤：
1. <探查动作> → 预期产物
2. <处理动作> → 预期产物
3. <验证动作> → 通过条件
风险与回退：<最可能坏在哪，坏了怎么办>
预计规模：<文件数/行数/时长量级>
```

- 计划的步骤必须可独立验证；"然后处理一下"这种不可验步骤是坏计划。

## 8. 汇报口径

- 结论先行：第一行给用户要的答案。
- 过程折叠：工具调用明细用户可展开（UI 卡），回复正文不重复流水账。
- 数字带出处（哪次测量/哪个文件）；不确定标注置信度与验证计划。
- 中途汇报：长任务每完成一个阶段报一次"进度 + 下一步"，不是憋大招。

## 9. 失败恢复

| 症状 | 首选动作 |
| --- | --- |
| invalid_argument | 读错误里的 field/suggestion，修参数重发 |
| permission_denied | 向用户说明并请求放行；不要换工具绕 |
| sandbox_violation | 路径越界 —— 改工作区内相对路径 |
| timeout | 缩小任务粒度或加 wait 条件 |
| 同工具连续 2 次失败 | 停：换策略/换工具/问用户 |
| 页面样式不对 | HtmlAnalyzeLayout 静态 + BrowserAnalyzeLayout 动态双查 |
| SYSTEM_LOCKED | 等待人工接管结束，改做其他任务 |

## 10. 权限语义

| 返回 | 含义 | 你的动作 |
| --- | --- | --- |
| allowed（自动/规则） | 已放行 | 继续执行 |
| ask + 用户同意 | 逐次确认通过 | 继续，同类动作可能再问 |
| ask + 用户拒绝 | 用户拒绝 | 停该类动作；解释替代方案 |
| denied_by_policy | 策略硬拒 | 换路径或放弃该子目标，明确告知 |

- 纪律：拒绝后**禁止**同参数立即重试（会被视为攻击性行为）；
  要么换方法要么升级给用户决定。

## 11. 交付纪律

- 产物必须有"完成定义"：文件落盘 + 自验证通过（布局检查/测试/构建）+
  用户可见入口（预览/路径）。
- 清单式收尾：列出新增/修改文件、验证结果、已知限制三段。
- 不留半成品状态文件；临时产物清理或移入 tmp/ 并说明。

## 12. 搜索任务流

标准流：明确问题 → 拆检索词（中英双语都试）→ WebSearch（多源）
→ 对高价值结果 WebFetch 深读 → 交叉验证（≥2 独立来源）→ 
引用格式输出（标题+URL+要点）。

- 时效问题加时间限定词（"2026"）；技术版本问题锁定版本号检索。
- 冲突信息处理：并列呈现来源与差异，标注置信度；不静默择一。

## 13. 数据任务流

1. 摸底：FileRead 头部 + 行数 + 编码（file 命令/CodeRead 分页）。
2. 小样本试 Transformation（1-10 行）→ 确认口径再全量。
3. 全量处理：优先结构化工具（CsvQuery/JsonPath）；复杂逻辑写脚本
   落 scripts/ 并执行。
4. 校验：行数对账、抽样肉眼、聚合数复核。
5. 出口：报告给结论 + 数据文件给路径。

- 大文件纪律：分页读（offset/limit）；禁止一次性读入超大文件撑爆上下文。

## 14. 写作任务流

- 先问清受众/场合/长度/语气（或从历史推断并显式确认）。
- 大纲先行（用户可改）；正文一次成稿 + 一轮自修订（结构/冗词/事实）。
- 长文档分文件落盘；回复里给摘要 + 文件路径。
- 引用事实必须检索验证；无法验证的显式标注"未核实"。

## 15. 编码任务流

跨语言通用纪律：

1. 读现状（CodeRead 相关文件 + 目录结构）—— 禁止凭想象写代码。
2. 最小改动原则：能用一行解决不用十行；不动无关代码。
3. 新代码跟随所在文件风格（命名/注释/缩进对齐现有）。
4. 验证：跑该语言的构建/测试（TerminalRun）；有静态检查就跑检查。
5. 提交说明用仓库规范格式（type(scope): 摘要）。

- 语言细节去对应语言专家知识库（Kotlin/Android/Python/… 各有专属库）；
  本库只管跨语言工作流。

## 16. 页面任务流

1. 需求确认：目标设备宽度（移动/桌面）、暗色、交互深度。
2. 骨架：header/main/aside/footer 语义标签 + viewport meta。
3. 样式：优先框架类（Tailwind 口径）；避免深嵌套与固定宽度（>375px 风险）。
4. 自查：HtmlAnalyzeLayout（骨架速览/响应式/a11y 问题清零或说明保留理由）。
5. 交付：文件路径 + 预览入口提示（工具卡会挂预览按钮）；
   用户要视觉确认时建议打开预览的布局检查器（Layers 开关）。
6. 需要真实渲染几何（重叠/滚动 bug）：BrowserNavigate + BrowserAnalyzeLayout。

## 17. 流水线模式

多阶段批量任务（转码/批量生成/爬取）：

- 每阶段产物落 tmp/ 中间目录；阶段间用文件衔接（可断点续跑）。
- 失败粒度：单项失败不炸整批 —— 记录失败清单，末尾汇总重试一次。
- 幂等：重跑覆盖产物（同输出路径直接覆盖，不做追加重复）。

## 18. 长任务模式

- 分段提交：每段自验证；上下文只保留必要摘要（19 节）。
- 检查点：把"已完成到哪"写进工作区 tmp/progress.md —— 
  会话中断后可从文件恢复（23 节）。
- 汇报节奏：阶段完成即报，不等全部完成。

## 19. 上下文预算

- 大输出瘦身：文件只读相关段（CodeRead offset/limit）；
  工具输出用 include_tree=false 之类的开关；
  搜索类先窄后宽。
- 压缩信号：系统提示触发压缩时，重要中间结论先固化到文件，
  防压缩丢失。
- 优先级：用户消息 > 当前任务状态 > 工具输出摘要 > 历史。

## 20. 输出治理

- 单工具输出上限意识：>30KB 的输出必须分段/过滤（grep/head 管道）。
- 报告类交付默认 Markdown；表格优先于长段落。
- 代码块带语言标注；行号引用用 `N:` 前缀口径（CodeRead 契约）。

## 21. 并行调用

- 独立读操作可并行（多文件 CodeRead 同时发）；
  写操作默认串行（防竞态）。
- 并行度克制：2-4 并发，过量会让用户看不清进度。

## 22. 子任务拆分

拆分判据：子任务有独立产物 + 独立验证；边界用文件衔接。
反模式：按"代码行数"拆 —— 按职责拆。

## 23. 会话恢复

- 恢复信息源：tmp/progress.md + 产物文件本身 + 会话历史。
- 恢复第一步：盘点现状（ls + 读 progress）再继续 —— 
  禁止凭记忆直接续写。

## 24. 跨域陷阱

| 陷阱 | 后果 | 预防 |
| --- | --- | --- |
| 把猜测当事实 | 幻觉输出 | 不确定就检索/读文件验证 |
| 工具面记忆过时 | 用不存在的参数 | 先读 schema/描述 |
| 单位混乱（ms/s、KB/字） | 数据事故 | 计算前显式换算列出 |
| 语言混用（面向用户语言 vs 代码语言） | 交付物语言错乱 | 先确认目标语言 |
| 深链路径假设 | 404/错乱 | 一切路径先 ls 确认存在 |

## 25. 排查总树

```text
东西不对？
├─ 报错文本有 → 读错误（分类）→ 对症
├─ 没报错但结果错 → 先复现（最小化）→ 二分定位（输入/数据/逻辑）
├─ 环境 vs 代码 → 换环境重跑 / 换数据重跑
└─ 只在某机器 → 环境 diff（版本/权限/路径）
卡住？
├─ 等外部（网络/构建）→ wait 工具盯
├─ 死循环 → 计数器 + 超时
└─ 依赖缺失 → 诊断工具探链路
```

## 26. 文本进阶：Unicode 与字素

- 字节 ≠ 码点 ≠ 字素：一个 emoji（如肤色修饰的组合）可能是
  1 个字素 = 2 个码点 = 8+ 字节 —— `"👍".length` 在多数语言里 ≠1。
  计数、截断、光标移动前先问：我要的是字素数还是码点数？
- 归一化四形：NFC（合成，Web 推荐）/NFD（分解，macOS 文件名）/
  NFKC/NFKD（兼容分解，慎用 —— 会改变语义）。
  字符串相等判断前先统一归一化，否则 "é" 的两种形态判不等。
- 大小写映射不安全：跨语言的边缘字符（如 Turkish İ）映射不同 ——
  不区分大小写比较用语言感知 API，别 toLower==toLower 硬比。
- 中文场景：全角/半角混排先统一口径（Ａ vs A 视觉同、比较异）；
  CJK 扩展区生僻字可能在 BMP 之外 —— 按字素/UTF-32 口径处理。
- 截断纪律：按字素边界截（组合附标别切半）；
  显示宽度 ≠ 码点数（终端里中文/emoji 是 2 宽字符）。
- 去重/计数/排序仍走 13 节数据流，但集合运算前先归一化。

## 27. 数值进阶：浮点与边界

- 二进制浮点陷阱：`0.1+0.2 !== 0.3`（二进制无法精确表示 0.1）。
  金额用整数最小单位（分）或十进制定点库（decimal），
  永不用 float 存钱；展示层再格式化。
- 整数边界：32 位上限 2^31-1（溢出变负）；JS Number 安全整数
  上限 2^53-1 —— 超过用 BigInt 或字符串传输（后端 id 类字段高危）。
- 浮点聚合：累加顺序不同结果不同 —— 对账用整数/定点，
  或 Kahan 求和；相等判断用容差（|a-b|<ε）而不是 ==。
- 单位换算纪律不变：算前写清单（KB=1000 / KiB=1024、
  Mbps÷8=MB/s、度+分/60+秒/3600），算完抽查反算一次。
- 时间戳位数判别：秒级 10 位、毫秒级 13 位 —— 混用会得到
  1970 年或 5138 年的荒谬日期（对账先看位数再怀疑库）。
- 随机数：默认 PRNG 不可用于安全场景 —— 密钥/token 用
  CSPRNG（secrets 级），可复现实验记录种子（84 节）。

## 28. 时间进阶：DST 与单调钟

- DST 陷阱：夏令时切换日的 "凌晨 2:30" 可能不存在或出现两次 ——
  日历/定时任务遇到必须显式决定取哪一侧；排期工具做
  "每天 2:30 的任务"会在切换日出错（真实事故高发区）。
- 中国无 DST，但跨时区协作（欧美同事/海外服务）一定踩 ——
  存储 UTC + IANA 时区名（Asia/Shanghai），不存"本地时间字符串"。
- 时长 vs 时刻不变：duration（2 小时）与 instant（14:00+08:00）
  严格分开；跨 DST 的"2 小时后"用日历运算而非 +7200s。
- 单调钟 vs 墙钟：测耗时/超时/重试用单调钟（不受 NTP 回拨
  影响）；时间戳展示用墙钟 —— 系统时间被回拨时，墙钟超时
  会永远不触发（“重试挂死”经典根因）。
- 序列化 ISO-8601（带偏移）；epoch 毫秒做交换最稳（27 节位数纪律）。
- 历法边缘：闰秒（UTC 有、Unix 时间戳平滑跳过）、闰年 2/29、
  月天数 —— 一律用日历库算，手写 30/31 对照表必错。

## 29. 编码进阶：乱码考古与归一化攻击

- 乱码三步升级：file/uchardet 看编码（给置信度不是铁口）→
  iconv 转码（加 `-c` 丢非法字节前先 dry-run 统计丢多少）→
  落盘后再读；原文件转码前必须留备份。
- 双重编码考古：UTF-8 被误按 GBK/Latin-1 再编码会出
  "娆囧悕"类汉字碎片 —— 修复路径是逆向转回（先转回错误编码
  再转 UTF-8）；判据：看乱码字形分布（双字节汉字 vs 单字节扩展）。
- GBK 边缘：GBK 不是 GB18030 的严格子集（€ 符号位冲突）——
  中文交换一律 GB18030/UTF-8；Excel 导出的 CSV 常带 GBK+BOM。
- 归一化攻击（安全面）：Unicode confusables（西里尔 а vs
  拉丁 a）可绕过敏感词/文件名/域名校验 ——
  校验前 NFKC 归一化 + confusable 检测（26 节四形口径）。
- URL/文件名：百分号编码是字节级（先 UTF-8 再 %-escape）；
  全角"／"与半角"/"视觉同、语义异 —— 排序/去重前归一。

## 30. JSON 进阶：大文件与 Schema

- 大文件纪律：>50MB 的 JSON 禁整读 —— jq 流式逐元素
  （`.[]` 管道消费）或语言侧流式解析器（ijson/Jackson
  streaming）处理；上下文只进摘要（19 节预算）。
- Schema 先行：接口类 JSON 用 JSON Schema 定契约
  （字段/类型/必填），消费端在边界先验证再解析 ——
  脏数据拦在门口，不渗透业务层。
- 语义陷阱：重复键（多数解析器"后者胜"，校验要显式拒）；
  数字精度（超长整型/金额会丢精度 —— 大整数序列化为字符串）；
  NaN/Infinity 在严格 JSON 里非法。
- 键序不保证：规范不承诺对象键序 —— 依赖键序的逻辑
  （diff/对账）先 canonical 化（键排序后再序列化比对）。
- 注入面：JSON 嵌入 HTML 时字符串里的 `</script>` 会终结
  标签 —— 序列化时转义 `<`/`>`；"JSON 一定安全"是错觉。
- 工具链：结构化查询用 JsonPath 工具（语义工具优先）；
  复杂变换脚本化落 scripts/ 可复跑（15 节纪律）。

## 31. 表格进阶：CSV 注入与类型陷阱

- CSV 公式注入（OWASP 口径）：以 `=` `+` `-` `@` 开头的单元格
  在 Excel/WPS 会被当公式执行（`=cmd|'/c...'` 类可 RCE）——
  导出侧给这些前缀加 `'` 转义；导入侧禁自动执行。
- Excel 类型强暴：身份证/手机号变科学计数、前导 0 丢失、
  "1-2" 变日期 —— CSV 本质是文本，列类型在消费端显式声明；
  给人用的导出附说明（文本格式导入）。
- RFC4180 边缘：字段含逗号/引号/换行必须双引号包裹、内部
  引号翻倍；换行在引号内合法 —— 行数 ≠ 记录数，
  解析必须状态机（手写 split(',') 必错）。
- 嗅探纪律：先 head 看原始行（分隔符/引号风格/编码/BOM），
  再定解析参数 —— 参数猜错全表错位。
- 大表：>10 万行用 DuckDB/数据库导入跑聚合（别全量驻内存）；
  Excel 列上限 16384 —— 超宽表先转置或拆分。
- 对账三层：列数一致 + 主键唯一 + 数值列可解析（逐层报错定位）。

## 32. 正则进阶：灾难回溯与 ReDoS

- 灾难回溯（catastrophic backtracking）：嵌套量词 + 上下文
  重叠（`(a+)+`、`(a|a)*`、`.*.*b`）在"不匹配"输入上指数爆炸 ——
  "正则把服务跑挂了"几乎都是这一类。
- 防御三板斧：
  1. 消歧 —— 能字符类就别交替（`[a-z]+` 优于 `(a|b|c)+`）；
  2. 原子组/占有量词 —— `(?>...)`、`a*+` 直接丢弃回溯点
     （JS 需 v 标志；RE2/Go 系引擎天然线性无回溯）；
  3. 锚定收窄 —— 行锚 + 明确字符类，别让 `.*` 满场跑。
- ReDoS 是攻击面：用户输入进正则前限长（如 ≤1000 字符）；
  线上正则过扫描器（snyk 类）+ 执行超时熔断。
- 结构化文档红线不变：JSON/HTML 永远用解析器
  （本仓库 LightweightHtmlParser 口径），正则只做行级清洗。
- 引擎差异：回溯引擎（PCRE/JS）与线性引擎（RE2）性能曲线
  完全不同 —— 同一模式换引擎前实测（119 节判例）。

## 33. Markdown 进阶：渲染安全与歧义

- CommonMark 不是"你想的 Markdown"：嵌套列表缩进判定、
  围栏内嵌套围栏（外层用更长的 ```）、行尾两空格才是硬换行 ——
  渲染器间差异真实存在；跨端一致以 CommonMD 规范裁决，
  别拿"GitHub 上看起来对"当标准。
- 注入面：Markdown 允许内嵌原生 HTML —— 渲染前必须
  白名单过滤（script/style/iframe/on* 属性全剥）；
  链接协议白名单（http/https/mailto），`javascript:` 会被
  "看起来无害"的 [x](javascript:...) 夹带。
- 歧义判例：有序列表后无空行的段落归属；`***` 是 hr 还是
  加粗斜体；表格管道符在代码 span 里不用转义。
- 表格纪律：单元格内放不了代码块/列表 —— 复杂内容退化为
  列表或代码块承载；管道符转义 `\|`。
- 生成纪律（工具产出口径）：标题不跳级、列表符号统一 `-`、
  代码块必标语言；本仓库：中文正文 + 英文术语首现注释。

## 34. Shell 进阶：引号与失败语义

- 三种引号三种语义：单引号（字面）> 双引号（展开 $ 与 `）>
  无引号（展开 + 分词 + glob）—— 路径带空格/中文时
  `"$var"` 不加引号就分词成多参数（事故高发第一位）。
- 失败语义：脚本默认不因命令失败而停 —— `set -euo pipefail`
  是起点（pipefail 让管道中段失败不被尾部吞掉）；
  但 -e 对条件上下文（if/&&/||）不触发，关键步骤显式 `|| exit`。
- sed -i 陷阱：GNU 与 BSD 参数不兼容（BSD 要求备份后缀）；
  且 -i 直接覆盖原文件 —— 跨平台脚本先输出 tmp 再 mv（幂等可重跑）。
- 管道子 shell 陷阱：`cat f | while read` 里变量的修改出不了
  循环 —— 用进程替换 `done < <(cmd)` 或 awk 收尾。
- xargs 分隔符：文件名可能含空格/引号 ——
  `find -print0 | xargs -0` 是唯一安全对（117 节 NUL 纪律）。
- 幂等判据：同脚本跑两遍结果一致（先清产物再生成）；
  rm 类危险动作先 dry-run 列目标清单（48 节剧本）。

## 35. git 进阶动作速记

（高频基础动作不必查库；本节只记"救火级"进阶动作，
详细纪律跳 Git 专家库 git.md）

- 历史救火：`git reflog` 是后悔药（`branch rescue HEAD@{N}`
  打分支接住）；rebase 到一半弃疗 `--abort`；
  改写历史前必打 backup 分支（成本 0，保命）。
- 二分自动化：`git bisect run ./check.sh`（exit 0=good）——
  数百提交内的回归 8 轮定位（101 实录见 git.md）。
- 冲突复用：`rerere.enabled=true` —— 同一冲突解一次，
  后续 rebase/merge 重放自动套用（多轮 rebase 救星）。
- 大仓提速：`git clone --filter=blob:none`（blobless：
  按需取文件内容，克隆近浅克隆速度但保留完整提交史）；
  配 sparse-checkout 只检出所需目录（CI 提速标配）。
- 洗史纪律：`rebase -i` 只理未推送历史；栈式分支用
  `rebase --update-refs` 连带更新上层分支引用。
- 事故红线：已推送分支禁 reset/force（revert 是唯一正路）；
  推送用 `--force-with-lease` 且仅限自己的短命分支；
  密钥入库 = 立即轮换 token（历史清理是第二步）。

## 36. 格式进阶：魔数欺骗与 polyglot

- 魔数只做初筛：zip 系（PK 头，覆盖 docx/apk/jar/epub）本质是
  容器 —— 真类型看内部目录结构；PNG 的 \x89PNG 头对了
  不代表尾部没夹带数据（PNG 后可挂任意附加段）。
- polyglot 文件：可同时是两种格式（GIF+JS、PDF+HTML）——
  上传校验不能只信魔数：白名单 + 图片重编码（解码再编码
  抹掉附加段）+ 病毒扫描三件套。
- 嗅探 vs 声明：浏览器按 Content-Type + 内容嗅探双轨判定 ——
  服务端配 `X-Content-Type-Options: nosniff` 关嗅探，
  否则"图片"里藏的 HTML 会被当页面渲染（存储型 XSS 入口）。
- 压缩层叠：gzip/zip 外层 + 内层格式 —— `file` 只报最外层；
  分析前先解包到独立目录（37 节纪律）逐层辨识。
- 判例："能读文本"但含 \x00 的文件多半是 UTF-16（BOM 判定）；
  \r\n 密集提示 Windows 出身 —— 转码前先定原始编码（29 节）。

## 37. 压缩进阶：选型与防御

- 选型按内容：zstd（快 + 压缩比好，新默认）/ xz（极致压缩、
  慢，发布产物用）/ gzip（兼容性兜底）/ brotli（Web 传输）。
  tar.gz 是万金油但不必唯一 —— 内部工具链统一 zstd 可省一半时间。
- gzip 非确定性：默认嵌入原文件名与时间戳 —— 可复现构建
  用 `gzip -n`（或 tar 配 --sort=name --owner=0 --numeric-owner）。
- zip 炸弹：嵌套压缩可把 42KB 膨胀到 PB 级 —— 解压不可信来源
  先 `unzip -l` 看清单，流式解压配解压后大小配额。
- 路径穿越（zip-slip）：恶意 zip 内含 `../../etc/x` 条目 ——
  解压进独立目录 + 校验每条路径不出目标目录。
- 打包前列清单（避免漏/多）不变；解包永远 `-C dir/` 进独立目录
  （防散落一地）。
- 归档 ≠ 备份：备份必须验证过可恢复（真解压 + 校验和抽查），
  没验证过的备份等于没有（113 节迁移对账口径）。

## 38. 网络进阶：DNS 与 TLS 分层诊断

- 分层定位纪律（别一上来就"网断了"）：
  DNS（getent hosts / dig @公共DNS 对照，看解析生效与污染）→
  TCP（nc -zv host 443，端口通不通）→
  TLS（openssl s_client -connect，证书链/SNI/协议版本）→
  HTTP（curl -sv，状态码与握手耗时）。
- DNS 缓存层：hosts 文件 → 系统 cache → 递归 DNS ——
  "别人好了我还旧"多半是 TTL 内缓存；直接问权威侧对照定位。
- TLS/QUIC 时代坑：TLS1.3 握手 1-RTT、HTTP/3 走 UDP ——
  老防火墙只放行 TCP 会静默失败；证书过期/SNI 缺失
  都在握手层报错（curl -v 的 TLS 段一眼定位）。
- 代理变量：HTTP(S)_PROXY 会让"本机直连"全走代理 ——
  诊断用 `env -i` 起干净环境对照；内网域名常需 NO_PROXY。
- 下载纪律不变：DownloadFile 工具（进度/重试）；批量限速礼貌；
  大文件断点续传（curl -C -）。

| 单位/时区没对齐 | 数据事故 | 27/28 节清单 |
| 幻觉引用（不存在来源） | 信任崩塌 | 引用必须来自检索结果 |

## 43. 剧本·数据搬家

场景：把 A 目录的 CSV 清洗后合并入 B 目录的汇总表。

1. 摸底：ls 两个目录；head 每个 CSV（列结构/编码/分隔符）。
2. 小样本：取首个文件前 5 行试清洗规则 → 用户确认口径。
3. 全量：脚本落 scripts/merge.py（tmp/ 中间产物）；跑批。
4. 对账：输入行数 vs 输出行数（差异要有解释：过滤了多少、为什么）。
5. 交付：汇总表路径 + 对账数字 + 样本抽查结果。

## 44. 剧本·批量重命名

1. 列清单（FileGlob 模式）→ 先 dry-run 输出"旧名 → 新名"对照表。
2. 用户确认后执行（mv 逐个；失败项收集不中断）。
3. 收尾报告：成功 N / 失败 M（原因清单）。

- 纪律：重命名不可逆操作先备份或入 git。

## 45. 剧本·网页汇总

场景：读 N 个页面提取要点汇总成报告。

1. 列 URL 清单；逐个 BrowserNavigate（wait_for 稳定元素）。
2. ExtractContent article 模式拿正文 → 存 tmp/pages/。
3. 汇总脚本/手工提炼 → reports/summary.md。
4. 引用格式：每要点带来源 URL；冲突信息并列（12 节）。

## 46. 剧本·环境体检

1. TerminalDiagnostics 探链路（会话/后端/exec）。
2. df -h（磁盘）/ free（内存）/ 网络连通（ping/curl）。
3. 版本盘点（工具链版本清单表）。
4. 产出体检报告：正常项 / 异常项 / 建议。

## 47. 剧本·定时任务

- 一次性提醒：日历/通知类工具（设备族）。
- 周期性任务：WorkManager 口径（Android 侧）或系统 cron（Linux 环境）——
  说明调度下限（系统节流）与真实触发间隔的差距。

## 48. 剧本·批量修复

场景：一类问题在多文件重复出现（如过期 API 批量替换）。

1. 定位全集（grep 模式）→ 清单。
2. 单文件修复 + 验证（构建/测试过）→ 固化手法。
3. 批量应用（逐文件：改 → 跑验证 → 下一个）；失败回退该文件。
4. 收尾：成功/失败清单 + 抽样 diff 展示。

## 53. 通用排查剧本

任何"东西不对"的第一小时动作序列：

1. **复现**：写清触发条件（输入/环境/时序）；间歇性问题加日志点。
2. **最小化**：砍到最小可复现（数据/步骤/依赖逐项剥离）。
3. **二分**：在怀疑链路中间下断点（日志/单测）判断坏在前半还是后半。
4. **对因**：根因确认（改这一处，问题消失且不引入新问题）。
5. **回归面**：同类风险点全查（同模式的其他调用点）。

## 54. 验证手法

| 手法 | 适用 |
| --- | --- |
| 构建过 | 代码类（编译/类型检查） |
| 测试过 | 有测试基线的模块 |
| 静态检查过 | lint/analyze 类工具 |
| 布局检查过 | HTML 产物（双工具） |
| 对账过 | 数据类（行数/聚合数） |
| 抽样过 | 大批量产物（人工抽查 3-5） |
| 交叉源过 | 事实类（≥2 独立来源） |

- "过"的定义是工具输出明确成功（exit 0 / 通过计数），不是"看起来没报错"。

## 56. 沟通模板

- 开工确认：`我理解的目标是 X；计划 1…2…3；预计 N 步；两点风险是 A/B。开始吗？`

## 65. 安全红线

- 不超范围改动（改动集与任务一致）。
- 不留孤儿产物（临时文件交代去向）。

## 92. HTTP 进阶：缓存与重试语义

- 缓存判定三件：Cache-Control（max-age/no-store/private）>
  ETag/If-None-Match（内容指纹）> Last-Modified（秒级粒度，弱）。
  "改了用户还看旧的"：分清浏览器层 max-age 与 CDN 层 s-maxage
  谁在兑着（两层 TTL 各自算）。
- 304 是响应不是错误：body 为空正常；但 POST 后立刻 304 ——
  多半是条件头被重试中间件错误复用（If-None-Match 跨请求泄漏）。
- 重试按码分流：408/429/503 可重试（尊重 Retry-After 头）；
  401 刷新凭证后重试一次；400/403/404/409 重试无意义（改请求）；
  502/504（网关层）与 500（应用层）分开统计归因。
- 重试纪律：指数退避 + 抖动（防同步雪崩）；只重试幂等请求
  （GET/PUT/DELETE + 带幂等键的 POST）；连续 5xx 报障不硬刚。
- 语义边界：PUT 全量替换（缺字段=清空）、PATCH 才是部分更新；
  409（版本/重复冲突）与 422（校验不过）分开 ——
  前端提示语完全不同。
- 请求纪律不变：显式 User-Agent；批量限速；
  连接层错误（拒绝/超时）与 HTTP 错误码分开归因（38 节）。

## 100. 配置进阶：分层与泄漏防线

- 分层覆盖模型：默认值（代码内）→ 配置文件 → 环境变量 →
  启动参数（右覆盖左）；启动时一次性校验（缺必填/类型错
  直接 fail-fast），不等到运行中炸。
- 作用域显式声明：export 只影响当前会话与子进程；rc 文件跨
  会话；系统级配置影响所有用户 —— 给用户讲清"改哪一层、
  何时生效、如何回退"。
- 泄漏防线三查：.env 永不入仓（gitignore + 提交扫描）；
  日志打印配置对象前先脱敏（密钥类键名 mask）；
  调试输出（printenv / docker inspect）可能带密钥 —— 分享前过滤。
- 密钥来源优先级：平台 secrets/保险库 > 部署环境注入 >
  本地 .env（仅开发）；轮换要有流程（泄露即时换 + 审计面）。
- env 陷阱：键名大小写敏感；容器会继承父进程变量（污染）——
  "读不到/读到旧值"先 `printenv` 盘点当前实际环境再排查。

## 101. 进程进阶：信号与退出码

- 退出码约定：0 成功；1-125 应用自定义；127=命令不存在；
  126=不可执行；128+N=被信号 N 杀死 —— 脚本分层返回码
  （4=参数错/5=依赖缺），调用方按码分支而不是解析 stdout。
- 僵尸/孤儿：子进程死而父不收（zombie 占进程表项）——
  批量 spawn 必须收割（wait）；进程泄漏 = 父进程没回收。
- 优雅终止阶梯：SIGTERM（给清理窗口）→ 等宽限（3-10s）→
  SIGKILL（兜底）—— 直接 KILL 会丢半写状态（DB 事务/截断文件）。
- 管道与进程组：kill 默认只杀单进程，管道链要杀进程组
  （负 PID / pkill -g）；nohup/setsid 让任务脱离终端
  （会话断开不被 SIGHUP 波及）。
- 工具映射不变：TerminalCreate 句柄管理会话；TerminalSignal
  发信号（先 TERM 后 KILL）；长任务后台化不占交互会话。

## 102. 权限进阶：umask 与危险位

- umask 决定新建文件默认权限（022 → 文件 644/目录 755）——
  "新文件别人可读"是 umask 说的；敏感目录先 umask 077。
- 执行位语义：目录的 x 是"可进入"（无 x 则下层文件全不可达），
  r 只是"可列名" —— 共享目录只给 r 不给 x 能看到名字进不去。
- 危险位红线：setuid（以属主身份执行）是提权面 ——
  自写脚本禁 setuid；发现陌生 setuid 二进制按入侵排查。
- sticky 位：/tmp 的 o+t 表示"只能删自己的文件" ——
  共享暂存目录的正确姿势。
- 修复纪律：递归 chmod 分开跑（目录要 x、文件不要）：
  `find . -type d -exec chmod 755 {} +` 与 `-type f` 分开；
  改权限前 ls -l 留档可回滚；无权限读时说明而非硬试。

## 103. 换行与 BOM 判例

- BOM 是三个字节 EF BB BF：JSON 解析器见到直接报错
  （规范禁 BOM）；Python 读用 utf-8-sig、写出统一无 BOM；
  shell 首行 shebang 前有 BOM = "bad interpreter"（BOM 把 #! 吃了）。
- 换行三口径：LF（unix）/ CRLF（win）/ CR（古 Mac）；
  "整文件全 diff"多半是换行战争 —— .gitattributes 声明
  `* text=auto` 治本（跨平台协作必配，git.md 68 节）。
- 判别命令：`file f`、`cat -A f | head`（^M = CR）；
  转换：dos2unix / `tr -d '\r'`（注意 tr 是按字节处理）。
- 二进制安全不变：二进制永远 base64/落盘不进正文（36 节辨识）。

## 116. 信号进阶：优雅终止阶梯

- 不可捕获二兄弟：SIGKILL(9)/SIGSTOP 不可拦 ——
  它们不进进程的清理逻辑；"优雅关停"方案必须假设 SIGKILL
  随时会来（半写状态要可恢复：tmp 文件 + rename 原子落盘）。
- SIGPIPE：管道下游退出后继续写入触发（默认杀进程）——
  `head` 提前退出导致上游 sed "挂了"多半是它；
  长流水线显式处理或按需忽略（`trap '' PIPE`）。
- 信号兼职约定：SIGHUP 兼做"配置重载"（nginx -s reload 家族）——
  自研服务统一口径：TERM=优雅停、HUP=重载配置、USR1=重开日志。
- 转发纪律：进程管理器只给主进程发信号 ——
  shell 包装层（sh -c）不转发给子进程，入口用 `exec app`
  让应用成为主进程，否则停不掉。
- Ctrl-C 语义：SIGINT 是"请中断"不是"必须死" ——
  脚本 trap INT 做进度落盘后再退。
- 服务级停机编排：摘流量 → TERM → 宽限期轮询 → KILL 兜底
  （full_stack 库 113 节同款口径）。

## 117. 文本管道进阶：locale 与 NUL

- locale 影响排序正确性：中文/大小写排序在 C 与 zh_CN.UTF-8
  下不同 —— 脚本要确定性输出时显式 `LC_ALL=C sort`；
  给人看的才用本地化排序。
- NUL 安全三对：`find -print0 | xargs -0`、`grep -lZ | xargs -0`、
  `sort -z` —— 文件名含空格/换行/引号时唯一可靠的传递方式
  （34 节引号纪律的管道版）。
- 性能分层：ripgrep（rg）代码检索比 grep 快一个量级
  （并行 + 默认忽略 .gitignore）；sort 大文件用 -S（内存）
  与 --parallel；awk 单文件几十万行内够用，更大换 DuckDB。
- 去重保序：`awk '!seen[$0]++'`（sort -u 会重排）；
  comm 做交/差前必须先 sort（comm 的隐藏契约，不 sort 结果错且不报错）。
- 按列处理用 awk 单遍扫描（优于多个 grep 串联）；
  CSV 带引号嵌套时 awk -F, 会切错 —— 换专业解析（31 节状态机）。
- 管道调试：`set -x` 看中间态；`tee /dev/stderr` 分流观察
  不破坏管道结构。

## 118. 日期进阶：歧义与历法边界

- 歧义格式禁用：`03/04/05` 在 US/UK/ISO 三口径下是三个不同日期
  —— 解析入口强制 ISO-8601（YYYY-MM-DD），别猜用户意图。
- 无时区时间字符串是雷：`2026-10-24T10:00` 没有 Z ——
  各解析器默认不同（本地 vs UTC）；交换一律带偏移或 Z（28 节）。
- 排序友好口径：文件名/日志用 `YYYYMMDD-HHmmss`（字典序=时间序）；
  单月单日不补零会破坏字典序 —— 补零纪律。
- 周与月边界：ISO 周年（2026-W03）与自然年不同（跨年周按
  ISO 周一规则归属）；"本月第一天"在 DST 时区用日历库算，别手写。
- 时长口径：ISO duration（PT2H30M）做机器交换；
  "2.5 小时"小数表示要声明换算规则（展示层才做）。
- 相对时间（"3 天前"）只在展示层生成，永不入库
  （入库的是绝对时刻，展示时再算）。

## 119. 正则判例：Unicode 与引擎差异

- 中文匹配升级：`[\u4e00-\u9fa5]` 只覆盖基本区（漏扩展 B-F
  生僻字）—— Unicode 引擎用属性类 `\p{Script=Han}`
  （JS 配 u 标志；2024+ v 标志支持集合运算 `[\p{Script=Han}--、。]`）。
- \d 的引擎分歧：PCRE 默认 ASCII；Python3 的 \d 匹配全 Unicode
  数字（阿拉伯-印度数字也算）—— 要 ASCII 就显式 `[0-9]`。
- 词边界陷阱：`\b` 按"单词字符"定义 —— 中文/emoji 相邻时行为
  反直觉（JS 无 u 标志时按 16 位码元切）；关键处用显式断言。
- 捕获与性能：非捕获 `(?:)` 在重复组里显著省内存；
  命名组 `(?<year>\d{4})` 代替位置序号（可读 + 重构安全）。
- 行锚多行语义：`^$` 默认只锚字符串首尾 —— 多行要 m 标志；
  `.` 默认不匹配换行（s 标志才跨行）—— 跨行抓取别忘 s。
- 判例集（旧菜谱的进阶口径）：手机号 `1[3-9]\d{9}` 加边界
  `(?<!\d)`/`(?!\d)` 防长数字中段误命中；
  版本号用 `(0|[1-9]\d*)` 防前导零；
  HTML 永远用解析器不用正则（32 节红线）。

## 120. 换算进阶：带宽时延与 token 预算

- 带宽 × 时延 = 窗口（BDP）：100Mbps × 100ms RTT = 1.25MB
  在途数据 —— 单连接吞吐上限由 BDP 决定（"跑不满带宽"先算
  这个再怀疑限速）；批量小请求的瓶颈常是 RTT 不是带宽。
- 上下文 token 预算：中文 ≈1 token/字（量级），代码 ≈0.6-0.8
  token/词元 —— 大输出进上下文前先按"字节 ÷4"粗估
  （19 节预算纪律的换算入口）。
- 口径红线不变：1GB=1000MB / 1GiB=1024MiB（磁盘买卖按 1000、
  系统显示按 1024 —— 差 7% 是口径不是丢容量）；
  Mbps÷8=MB/s；UTF-8 中文 3 字节、emoji 4 字节（26 节字素口径）。
- 工程速算：1 天=86400s（缓存 TTL 基准）；
  QPS×86.4k=日请求量量级（容量速算）。
- 大数速判：2^10≈10^3 —— 估算够用；精确值用工具
  （BaseConvert）不心算硬答。

## 161. 文件进阶：海量文件与怪名

- 怪名防御（空格/换行/以 - 开头）：find 一律 -print0、
  xargs 一律 -0、rm 一律 `rm -- "$f"`（-- 防文件名被当选项）；
  `rm -rf *` 前先 ls 肉眼确认展开结果。
- 海量文件（>10 万）：一次遍历多输出（`find . -type f
  -printf '%f\n'` 后 awk 分类），别 find N 遍；
  复制迁移用 rsync（断点续传 --partial + 校验）。
- 属性保真复制：`cp -a`（含时间戳/权限/xattr，归档口径）；
  迁移场景（113 节）用 rsync -aHAX（硬链接/ACL）+ -c 校验和抽查。
- 目录差异对账：`diff -rq a b` 只报文件级；内容级用
  `rsync -rcn a/ b/`（校验和不复制）列内容差异清单。
- 符号链接纪律：cp 默认跟随链接（内容复制成实体）——
  保持链接用 cp -a / rsync -a；备份脚本忘了这项会体积膨胀。
- 时间取证三钟：mtime（内容改）/ ctime（元数据改）/ atime（读）
  —— "文件何时被动过"先问哪个钟。

## 162. 文本管道性能与正确性

- 工具选择顺序纪律：行级抽取 sed/head（快）→ 模式检索
  rg/grep → 结构化（CSV/JSON）专业工具 → 超大表 DuckDB。
  "选对工具"比"调参数"收益大一个量级。
- 正确性判例：
  - `grep -o pat | wc -l` 计"匹配次数"，`grep -c` 计"命中行数"
    —— 一行多命中时两口径天差地别（汇报前声明口径）。
  - sed 范围 `/BEGIN/,/END/` 嵌套时匹配到最近 END ——
    日志分段提取用 awk 状态机更可控。
  - tr 是字符级不是字符串级（换 CRLF 用 sed/awk，别 tr '\r\n'）。
- 性能判例：大文件先 sort 再 uniq -c（流式），比全量驻内存
  省十倍内存；rg 默认忽略 .gitignore 与二进制
  —— "怎么少了文件"先查这个。
- 增量处理：追加型日志用 `tail -F`（轮转安全）+ 位点状态文件
  记处理进度（85 节幂等衔接，重跑不重复处理）。
- 输出体量预估先行（>50KB 加过滤）—— 20 节输出治理不变。

## 163. 网络观测进阶：curl/mtr 深水

- curl 计时分解（一次请求看清慢在哪层）：
  `-w "dns:%{time_namelookup} tcp:%{time_connect} tls:%{time_appconnect} ttfb:%{time_starttransfer} total:%{time_total}\n"`
  —— TTFB 远大于 TLS 段说明服务端慢；TCP 连不上是网络层不是应用层。
- 主机钉定调试：`curl --resolve api.x.com:443:1.2.3.4`
  （把域名钉到指定 IP）—— 灰度/迁移验证不靠改 hosts。
- 重定向语义：-L 跟随默认最大 50 跳；301/302 上多数实现把
  POST 降级为 GET（历史包袱）—— 保方法的声明 307/308。
- TLS 观测：`openssl s_client -connect h:443 -servername h`
  看证书链/有效期/协商协议；curl -v 的 TLS 段定位
  SNI/证书/版本三类错（38 节分层）。
- 路径观测：mtr 比 ping+traceroute 直观（逐跳丢包/延迟列）；
  偶发丢包看持续采样（mtr -r -c 100），单次不可信。
- API 调试组合：`curl -s --fail-with-body`（4xx/5xx 报错且留
  body）+ `| jq` 结构化消费。

## 164. 系统进阶：瓶颈归因观测

- 资源四象限（CPU/内存/磁盘 IO/网络）先定位再深挖：
  load 高 + CPU 高 → `ps aux --sort=-%cpu | head` 找主；
  load 高 + CPU 低 → 多半在等 IO（iostat 看 %util/await，
  vmstat 看 wa 列）。
- 内存口径判读：free 的 available 才是可用量
  （buff/cache 可回收，别看 free 列报警）；
  "服务无声消失"先查 dmesg 的 OOM 记录（Killed process）。
- 磁盘两种满：空间满（df -h）与 inode 满（df -i，海量小文件）
  —— "明明有空间却写不进"查后者。
- 容器内观感偏差：容器看到的 CPU/内存是 cgroup 配额口径 ——
  load 异常而 top 正常时查 cgroup 限制与 throttling
  （CPU 被限流表现为周期性卡顿）。
- 长任务观测：nohup 后 jobs -l 确认 + tail 盯进度；
  退出码是判死唯一口径（101 节）。
- 环境变量、后台任务等基础动作不变（printenv X / jobs -l）。
